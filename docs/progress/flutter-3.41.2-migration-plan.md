# Flutter 3.41.2 Migration Plan

Created: 2026-02-22
Based on: Hands-on upgrade attempt from Flutter 3.38.2 to 3.41.2

---

## 1. Overview

Upgrading Flutter from 3.38.2 to 3.41.2 requires a cascade of major version bumps across several dependency packages. Simply changing the FVM version causes dependency resolution to fail.

### Why the upgrade is difficult

Flutter 3.41.2 internally requires `matcher 0.12.18` (via `flutter_test`), which triggers the following chain:

```
Flutter 3.41.2
  └── flutter_test (SDK)
        └── requires matcher 0.12.18
              └── requires test >= 1.28.0
                    └── requires analyzer >= 8.0.0
                          ├── requires freezed >= 3.0.0   (2.x only supports analyzer ^6–7)
                          └── requires riverpod_generator >= 3.0.0  (2.x only supports analyzer ^6–7)
                                └── requires riverpod_annotation >= 4.0.0
                                      └── requires flutter_riverpod >= 3.0.0
```

Additionally, the in-house library `plough` depends on `freezed_annotation ^2.4.4`, which conflicts with `freezed_annotation ^3.0.0` and requires a `dependency_overrides` workaround until it is updated.

## 3. Breaking Changes in Detail

### 3.1 freezed 2.x → 3.x

#### Class definition syntax change

In freezed 3.x, the mixin syntax `with _$ClassName` is replaced by `extends _$ClassName`, and the class must be declared `abstract`.

```dart
// freezed 2.x
@freezed
class MyModel with _$MyModel {
  const factory MyModel({required String name}) = _MyModel;
}

// freezed 3.x
@freezed
abstract class MyModel with _$MyModel {
  const factory MyModel({required String name}) = _MyModel;
}
```

#### `when` / `map` / `maybeWhen` no longer generated by default

freezed 3.x stops generating pattern matching helper methods by default, favoring Dart 3 `switch` expressions instead.

```dart
// freezed 2.x
result.when(
  success: (data) => ...,
  error: (msg) => ...,
);

// freezed 3.x — use Dart 3 switch expression
switch (result) {
  Success(:final data) => ...,
  Error(:final msg) => ...,
}
```

It is possible to opt back in with `@Freezed(map: FreezedMapOptions.all)` or similar options, but migrating to `switch` is the recommended path.

#### Collections become unmodifiable by default

`List`, `Map`, and `Set` fields are automatically wrapped in `UnmodifiableListView` etc. Any code that calls `.add()` or `.remove()` directly on these fields will throw a runtime error.

#### Affected files in this project

| File | Contents |
|---|---|
| `packages/core/settings/lib/src/model/settings.dart` | `Settings` model |
| `packages/core/app_config/lib/src/models/app_config.dart` | `AppConfig`, `StartupConfig`, `DevelopmentConfig`, etc. |
| `packages/core/workflow/lib/src/types.dart` | Workflow type definitions (large file; generated code ~2,000 lines) |
| `packages/features/settings/lib/src/providers/startup_providers.dart` | `StartupSettings` model |

### 3.2 riverpod 2.x → 3.x / riverpod_annotation 2.x → 4.x

#### Function-style provider signature change

In riverpod_generator 4.x, the first argument of a functional provider uses the generic `Ref` type instead of the named `XxxRef` type.

```dart
// riverpod_generator 2.x
@riverpod
String myValue(MyValueRef ref) => 'hello';

// riverpod_generator 4.x
@riverpod
String myValue(Ref ref) => 'hello';
```

The named `*Ref` typedef is still generated in the `.g.dart` file but is no longer written in source code.

#### `dynamic` types cause code generation failure

riverpod_generator 4.x throws `InvalidTypeException` when a provider's return type or parameter type contains `dynamic`.

```dart
// Fails to generate
@riverpod
Future<Map<String, dynamic>> myProvider(Ref ref) async { ... }

// Fix: replace dynamic with Object?
@riverpod
Future<Map<String, Object?>> myProvider(Ref ref) async { ... }
```

During this investigation, `globalPropertyTypeStatistics` in `packages/core/graph_flutter/lib/src/providers/global_property_type_providers.dart` hit this issue. That provider was unused (already commented out in `index.dart`) and the file was deleted.

#### `AutoDisposeProviderRef` / `AutoDisposeNotifier` removed

All `AutoDispose`-prefixed types are removed in riverpod 3.x.

```dart
// riverpod 2.x generated code
typedef MyProviderRef = AutoDisposeProviderRef<String>;
typedef _$MyNotifier = AutoDisposeNotifier<String>;

// riverpod 3.x generated code
typedef MyProviderRef = Ref<String>;
// _$MyNotifier now extends Notifier<String>
```

This affects every `.g.dart` file. **Re-running code generation handles this automatically** — no manual edits needed.

#### `StateNotifier` / `StateNotifierProvider` moved to legacy

`StateNotifier` and `StateNotifierProvider` are moved to `package:flutter_riverpod/legacy.dart` in riverpod 3.x.

Files in this project that use `StateNotifier` directly:

| File | Class |
|---|---|
| `packages/core/workflow/lib/src/registry.dart` | `TaskRegistry extends StateNotifier<...>` |
| `packages/features/metadata_editor/lib/src/providers/metadata_providers.dart` | `MetadataSegmentNotifier extends StateNotifier<int>` |
| `packages/presentation/components/lib/src/providers/sidebar_width_provider.dart` | `SidebarWidthNotifier`, `SecondarySidebarWidthNotifier` |
| `packages/presentation/components/lib/src/identifiable_widget/widget_id_manager.dart` | `WidgetIdManager`, `SelectionManager` |
| `apps/desktop/lib/src/providers/shell_state_manager.dart` | `ShellStateManager` |
| `apps/desktop/lib/src/providers/filter_providers.dart` | `FilterNotifier` |
| `apps/desktop/lib/src/commands/command_registry.dart` | `CommandRegistry` |

**Short-term fix**: add `import 'package:flutter_riverpod/legacy.dart';` to each file — no other changes required.
**Long-term**: rewrite using `Notifier<T>` / `AsyncNotifier<T>` as recommended by the riverpod 3.x migration guide.

#### `ProviderObserver` interface change

If any class implements `ProviderObserver`, its method signature has changed (arguments consolidated into a single context object). Verify whether this is used anywhere in the project.

#### Automatic retry and suspension behavior change

In riverpod 3.x, providers are paused when they go off-screen and automatically retried on error. This behavioral change may affect async providers and their associated tests. Run the full test suite after migration and investigate any unexpected failures.

## 4. Step-by-Step Migration Plan

### Phase 0: Prerequisites (estimated: 0.5 day)

1. **Update the `plough` repository** (highest priority — blocks everything else)
   - Bump `freezed_annotation` to `^3.0.0` in `plough/pubspec.yaml`
   - Apply freezed 3.x class definition changes
   - Regenerate code and verify it builds
   - Push to the `develop` branch

2. Create a working branch in this repository:
   ```bash
   git checkout -b feature/flutter-3.41.2-upgrade
   ```

### Phase 1: Update `.fvmrc` and all `pubspec.yaml` files (estimated: 1 hour)

Update version constraints across all 26 `pubspec.yaml` files and `.fvmrc`.

```bash
# .fvmrc
{ "flutter": "3.41.2" }

# Flutter SDK constraint — all 26 pubspec.yaml files
flutter: ">=3.41.2"

# Package version constraints
freezed_annotation: ^3.0.0
freezed: ^3.0.0
test: ^1.28.0
flutter_riverpod: ^3.0.0
riverpod_annotation: ^4.0.0
riverpod_generator: ^4.0.0
riverpod_lint: ^4.0.0
```

Add `dependency_overrides` to root `pubspec.yaml` (temporary, until `plough` is updated):
```yaml
dependency_overrides:
  freezed_annotation: ^3.0.0
```

Also update the Flutter SDK version reference in `CLAUDE.md`: `Flutter SDK: 3.41.2+`.

### Phase 2: Apply freezed 3.x changes (estimated: 0.5–1 day)

Update the 4 source files that use `@freezed` to conform to freezed 3.x syntax.

#### `packages/core/settings/lib/src/model/settings.dart`
- Change `class Settings with _$Settings` to `abstract class Settings with _$Settings`

#### `packages/core/app_config/lib/src/models/app_config.dart`
- Apply the same `abstract class` change to `AppConfig`, `StartupConfig`, `DevelopmentConfig`, and any other freezed classes in this file

#### `packages/core/workflow/lib/src/types.dart`
- Large file with many freezed classes and ~2,000 lines of generated code
- After updating class definitions, search the entire project for `when(` / `map(` calls on these types and migrate them to `switch` expressions

#### `packages/features/settings/lib/src/providers/startup_providers.dart`
- Apply the `abstract class` change to `StartupSettings`

**Run `flutter build macos` after each file change** (per the "one file at a time" rule in `CLAUDE.md`).

## 5. Important Notes

### Package processing order

Always process packages from lowest-level to highest-level to avoid cascading errors:

```
foundation_common / foundation_flutter
  ↓
graph_common / graph_flutter / stack_common / stack_flutter
  ↓
settings / app_config / events / localization / themes / undo / workflow
  ↓
app
  ↓
features/* / presentation/*
  ↓
apps/desktop
```

### Reinstalling `melos`

The globally installed `melos 6.x` is incompatible with the Dart SDK bundled in Flutter 3.41.2 (kernel binary version mismatch). Reinstall it before starting:

```bash
flutter pub global activate melos
```

### `flutter_gen_runner` deprecation warning

`core_localization/l10n.yaml` contains `synthetic-package: true`, which is deprecated in Flutter 3.41.2. Remove that line from `l10n.yaml` to eliminate the warning.

### Run the full test suite

riverpod 3.x changes the behavior of `ProviderContainer` (automatic retry, off-screen pausing). Run all tests after migration and investigate any unexpected failures:

```bash
melos run test
```

## 6. Issues Encountered During Investigation

### Issue 1: `plough` depends on `freezed_annotation ^2.4.4`

Bumping `freezed_annotation` to `^3.0.0` caused `pub get` to fail due to a conflict with `plough`.

**Workaround applied:** Added `dependency_overrides: freezed_annotation: ^3.0.0` to root `pubspec.yaml`. This allowed `pub get` to succeed.

**Root fix:** Update `plough` repository to support `freezed_annotation ^3.0.0` (Phase 0).

### Issue 2: `riverpod_generator 4.x` rejects `Map<String, dynamic>`

`globalPropertyTypeStatistics` in `global_property_type_providers.dart` returned `Future<Map<String, dynamic>>`, causing code generation to fail with `InvalidTypeException`.

**Resolution:** Confirmed the file was not imported or used anywhere in the project (`index.dart` had it commented out). Deleted the file entirely.

### Issue 3: `melos run gen:all` fails with Flutter 3.41.2

The globally installed `melos 6.x` crashes with a Dart SDK kernel binary version mismatch when Flutter 3.41.2 is active. Resolved by running `dart run build_runner build` individually per package.

### Issue 4: Stale `.g.dart` files cause mass build errors

Building before regenerating code left `AutoDisposeProviderRef` / `AutoDisposeNotifier` references from riverpod 2.x in the old `.g.dart` files, producing hundreds of "type not found" errors. Always complete code regeneration for all packages before attempting a build.

### Issue 5: freezed 3.x generated `_$` API breaks existing source

If old `.freezed.dart` files remain while source files still use `class X with _$X`, the compiler reports missing abstract method implementations from the new generated base class. Regenerating freezed code and updating the source class declarations must be done together.

## 7. Migration Completion Status

**Completed: 2026-02-23**

The migration was successfully completed. `flutter build macos` passes with Flutter 3.41.2.

### Additional issues resolved during execution (beyond the plan)

#### Issue 6: riverpod_generator 4.x renames `XxxNotifierProvider` to `XxxProvider`

In riverpod_generator 4.x, the generated provider name for `class FooNotifier` changed from `fooNotifierProvider` to `fooProvider` (Notifier suffix is stripped). This caused two problems:

1. **Name collision**: Source files that defined a `@riverpod` function `foo()` alongside a `class FooNotifier` produced two providers both named `fooProvider`. Resolution: deleted the wrapper function provider (e.g., `appConfig`, `pathfinderState`, `startupSettings`) and updated callers to use `fooProvider` directly.

2. **Stale references in source**: Many source files still called `fooNotifierProvider`. These were updated to `fooProvider` (e.g., `selectionStateNotifierProvider` → `selectionStateProvider`, `toolbarStateNotifierProvider` → `toolbarStateProvider`).

#### Issue 7: `AsyncValue.valueOrNull` renamed to `AsyncValue.value` in riverpod 3.x

In riverpod 3.x, `AsyncValue.valueOrNull` was renamed to `AsyncValue.value`. The behavior also changed: `.value` now returns `null` during error states (previously it could throw). All uses of `.valueOrNull` were replaced with `.value`.

#### Issue 8: `StateProvider` and `StateNotifierProvider` need `legacy.dart` import

`StateProvider` (simple state, not `StateNotifier`) also requires `import 'package:flutter_riverpod/legacy.dart';`. Files affected beyond those listed in the plan:

- `apps/desktop/lib/src/providers/app_state_providers.dart`
- `apps/desktop/lib/src/providers/dialog_visibility_providers.dart`
- `apps/desktop/lib/src/providers/entity_selection_bridge_providers.dart`
- `apps/desktop/lib/src/providers/ui_test_action_providers.dart`
- `apps/desktop/lib/src/widgets/outline_view.dart`
- `packages/app/lib/src/activity_bar/app_activity_bar.dart`
- `packages/core/themes/lib/src/color_scope.dart`
- `packages/features/metadata_editor/lib/src/providers/label_list_providers.dart`
- `packages/features/welcome/lib/src/providers/target_selection_dialog_providers.dart`
- `packages/features/welcome/lib/src/providers/welcome_providers.dart`

#### Issue 9: `searchfield ^1.3.3` incompatible with Flutter 3.41.2

Flutter 3.41.2 added `maintainLabelSize` to `InputDecoration.copyWith`. The `searchfield` package's `SearchInputDecoration.copyWith` did not override this parameter, causing a compile-time error. Updated to `searchfield: ^2.0.0` which adds this parameter.

### Remaining known issues (not blocking the build)

1. **`StateNotifier`/`StateNotifierProvider` uses are deprecated** — 7 files still use the legacy API. Long-term goal: migrate to `Notifier<T>` / `AsyncNotifier<T>`.
2. **`melos run gen:all` still broken** — global melos 6.x remains incompatible with Flutter 3.41.2 Dart kernel. Use per-package `dart run build_runner build` instead.
3. **`appearance_settings_view.dart` unused import warning** — `../../providers/settings_providers.dart` import is unused after adding `core_settings` import directly. Can be cleaned up later.
